## P1 — البنية التحتية والأمان ✅

**الهدف:** خادم حقيقي يقلع ويعمل بأمان على بيئة إنتاجية.

**ما أُنجز:**
- هيكل نظيف بالطبقات: `Repository → Service → Route` (لا SQL في الروتات).
- PostgreSQL + هجرات SQL (جدول تتبّع `schema_migrations`) + بذر آمن للتكرار
  (9 فئات + 12 رياكشن بكلمات مفتاحية عامية + 3 مجموعات + إعدادات).
- خادم Fastify 5 مع أخطاء موحّدة `{ error: { code, message } }`.
- مصادقة مسؤول (كلمة سر بيئية + جلسة HMAC 8 ساعات) + مصادقة مستخدم OTP (6 أرقام،
  مجزّأة SHA-256+ملح، صلاحية 15 دقيقة، استخدام مرة).
- واجهات قابلة للتبديل: `storage` (قرص محلي) · `mail` (Dev) · `media` (عقد معرّف لـ P2).
- فحص الأسرار عند الإقلاع: في الإنتاج يرفض البدء بأي سر مفقود/قصير/نمطي.
- Rate-limiting عام + حماية إضافية على مسارات OTP وتسجيل الدخول.
- إغلاق أنيق (Graceful shutdown).

**القرارات المهمة (وانحرافات مبرّرة):**
1. **إضافة التطبيع العربي في P1 بدل P3** — أثناء اختبار البحث اليدوي فشلت مطابقة "دين"
   مع الكلمة المفتاحية "دَين" (التشكيل). كان هذا عيبًا جوهريًا في وعد "البحث بالموقف"،
   فأضفنا `lib/arabic.js` + عمود `search_text` (هجرة 0002). قرار مبرر: التطبيع أساسي
   لقيمة المنتج ولا يستحق التأجيل.
2. **معرّف `slug` = display_id بصيغة صغيرة** مؤقتًا — الـ slugs الودودة للـ SEO تأتي في
   P3 عندما نعرف أسماء الملفات الحقيقية.
3. **صورة Docker على Node 22** (بدل 20) — تبعية `cookie@2.0.1` تتطلب Node ≥ 22؛
   Node 22 هو LTS الحالي، وهو الخيار الأسلم للإنتاج.

**الاختبارات:** 37 اختبارًا يمر (7 وحدة + 30 تكامل) ضد PostgreSQL حقيقي على قاعدة `yemreact_test`:
- فحص صحي + حالة قاعدة البيانات.
- الفئات التسع بالترتيب والألوان المصحّحة.
- قائمة الرياكشنات + فلترة + بحث بالتطبيع العربي.
- تفاصيل رياكشن + 404 بصيغة موحّدة.
- دورة دخول مسؤول كاملة (رفض/قبول/جلسة/إحصائيات).
- دورة OTP كاملة (طلب → تحقق → me → حفظ ومزامنة).
- فحص الأسرار (رفض القيم الضعيفة/الافتراضية).

**DoD تحقّق:** ✅ `npm install && db:setup && start` يعمل؛ دخول المسؤول يعمل؛ لا أسرار
افتراضية مقبولة في الإنتاج؛ `GET /health` يعيد `ok`؛ نشر Docker موثّق.

## P2 — معالجة الميديا ✅

**الهدف:** فيديو حقيقي من الرفع إلى النشر بمعالجة كاملة.

**ما أُنجز:**
- تنفيذ `MediaInterface` بـ ffmpeg (`FfmpegMedia`):
  - `probe()`: مدة + أبعاد + fps + الترميز + وجود صوت (عبر ffprobe).
  - `process()`: ترميز H.264/AAC + `faststart` + تحجيم ≤1080 + واترمارك القُصاصة
    (12% من العرض، ضمن نطاق 9–15% المقفل) + مصغّرة WebP من الملف الأصلي.
- مولّد الواترمارك (`lib/watermark.js`): يولّد PNG شفافًا من SVG (تقشّر ورقي + مثلث
  تشغيل + ظلّ مزدوج) ويُرستر عبر ffmpeg (svg_pipe). نسختان: `tr` و`tl` (قلب الكتلة).
- التحقق من الملفات (`lib/validate.js`): magic bytes (mp4/webm/mpegts/avi) + الحجم
  الأقصى (80MB) + المدة القصوى (12 ثانية).
- كشف التكرار: تجزئة SHA-256 متدفقة للملف الأصلي → حقل `content_hash` → رفض 409.
- خدمة معالجة (`media.service.js`): خط الإدخال الكامل (تحقق → تجزئة → فحص مدة →
  معالجة → تخزين → تنظيف الملفات المؤقتة).
- واجهة رفع المسؤول (`POST /api/v1/admin/reactions`): multipart حقيقي، يقرأ الفيديو
  والحقول النصية، ينشر فورًا (المسؤول = المراجع البشري) أو يحفظ كمسودة.
- خدمة الوسائط (`GET /media/*`): قراءة من واجهة التخزين + دعم Range (206) للسحب.

**القرارات المهمة (وانحرافات مبرّرة):**
1. **الواترمارك يُولَّد من SVG عند الإقلاع** بدل الاعتماد على أصول PNG مرفوعة —
   لأن علامة القُصاصة معرفة أصلًا كمسار SVG في التوكنز؛ هذا يضمن تطابقها حرفيًا مع
   النسخة المقفلة وقابلية إعادة توليدها على أي خادم.
2. **الصيغة الحديثة `scale=rw:rh` بدل `scale2ref`** — `scale2ref` أُهمل في ffmpeg 7
   وتبيّن أثناء الاختبار أنه لا يُنتج النتيجة المتوقعة (فشل الواترمارك بالظهور).
   الفلتر الحالي: `[1:v][vid]scale=w='rw*0.12':h='rw*0.12'` (مربع بلا تشويه).
3. **كشف التكرار قبل المعالجة المكلفة** — التجزئة تُحسب على الملف الأصلي أولًا،
   فيُرفض المكرر قبل إنفاق CPU على إعادة الترميز.
4. **المسؤول ينشر مباشرة** (status=published افتراضيًا) — لأن رفع المسؤول هو نفسه
   المراجعة البشرية المنصوص عليها؛ مساهمات المستخدمين تبقى Pending (P5).

**الاختبارات:** 12 اختبارًا جديدًا (إجمالي 49 يمر):
- magic bytes (قبول mp4 حقيقي / رفض نصي متخفٍ) + الحجم.
- probe (مدة/أبعاد/ترميز).
- process (فيديو H.264 + مصغّرة WebP حقيقية + رفض >12 ثانية).
- رفع كامل عبر HTTP (معالجة → نشر → ملفات قابلة للوصول + Range 206).
- كشف التكرار (409) + قائمة الإدارة.

**DoD تحقّق:** ✅ يرفع المسؤول فيديو → يُعالج تلقائيًا → يظهر بواترمارك وثمنيل
ومدة صحيحة؛ المكرر يُرفض بالـhash؛ الملفات تُخدَم مع دعم النطاق.

## P3 — المكتبة والاكتشاف ✅

**الهدف:** واجهة عامة (Astro SSG + جزر Preact) تعرض المكتبة وتمكّن البحث والتفاعل.

**ما أُنجز (الخلفية):**
- مسار الأحداث الحقيقية `POST /api/v1/reactions/:id/event` (view/save/download/share)
  مع: فلترة بوتات (403)، تجزئة IP بملح، منع تكرار العرض الفريد (نافذة 30 دقيقة)،
  واستثناء نشاط المسؤول.
- مسارا الاكتشاف: `GET /api/v1/featured` (مختار الأسبوع + جديد المكتبة) و
  `GET /api/v1/collections[/:slug]`.
- أُضيف `slug` لشكل الرياكشن العام، وخدمة ملفات ثابتة تقدّم بناء Astro من نفس الخادم.

**ما أُنجز (الواجهة — مجلد `web/`):**
- Astro 5→7 (SSG) + جزر Preact. صفحة رئيسية (بطل + بحث بالموقف + جُمل بذور + شريط
  تصنيفات + مختار الأسبوع + مجموعات + جديد المكتبة + شبكة) وصفحة تفاصيل `/r/[slug]`
  لكل رياكشن (14 صفحة تُولَّد وقت البناء).
- **التفاصيل:** فيديو ضمني صامت (نقرة للصوت، إعادة تلقائية)، كابشن/موقف/تصنيف كـ HTML
  دلالي ثابت (SEO)، أزرار تنزيل (بواترمارك)/حفظ/مشاركة بأحداث حقيقية، ورياكشنات قريبة.
- **SEO/OG:** وسوم OG ديناميكية (عنوان/وصف/صورة مصغّرة) لكل صفحة، canonical نظيف.
- **الأداء:** حزمة JS للجزيرة ~6KB، الصفحة ~10KB، صور WebP، تحميل كسول، فيديو preload=metadata.
- **التزام الهوية 100%:** `web/src/styles/tokens.css` مولّد من `design-tokens.js` (حارس
  اختبار يمنع الانحراف)؛ ألوان/خطوط/قُصاصة/قالب الكليب مطابقة.

**القرارات المهمة (وانحرافات مبرّرة):**
1. **رفع بيئة التطوير إلى Node 22 + Astro 7** — `npm audit` كشف ثغرات XSS عالية الخطورة
   في Astro ≤7.0.9 (الإصلاح في 7.2.2 يتطلب Node ≥22). صورة Docker أصلًا node:22، فرفعنا
   بيئة التطوير للتوافق، وصفر ثغرات الآن. (انحراف عن "Node 20" الموثّق سابقًا).
2. **توليد tokens.css من design-tokens.js** بدل كتابته يدويًا — يضمن عدم الانحراف،
   مع اختبار drift-guard.
3. **محتوى التفاصيل الأساسي (كابشن/موقف) ثابت في HTML** لا داخل الجزيرة — لتحسين SEO
   والتدرج الرشيق بلا JS (كان الكابشن يظهر فقط في JSON الجزيرة ووسوم OG).
4. **صيغة بناء `file`** (صفحات مسطّحة r/yr-0001.html) + خدمة ثابتة تدعم مسارات بلا امتداد.

**الاختبارات:** إجمالي 65 اختبارًا يمر (7 جديدة للواجهة + 9 للأحداث/الاكتشاف + حارس التوكنز):
- صفحات: الرئيسية (200 + بطل)، التفاصيل (h1 دلالي + OG + canonical بلا .html)، 404.
- البحث بالموقف عبر API، تسجيل الأحداث، فلترة البوتات، منع تكرار العرض.
- **فحص متصفح حقيقي (Playwright):** ديسكتوب + موبايل → 0 أخطاء console، 0 أخطاء page،
  0 طلبات فاشلة؛ 12 بطاقة تُحمَّل، البحث يعمل، 3 أزرار أفعال.

**DoD تحقّق:** ✅ مستخدم يجد رياكشنًا بجملة موقف عامية ويُنزّله بواترمارك؛ كل عداد
ناتج عن حدث حقيقي؛ الصفحة تُفتح بمسار حقيقي بمعاينة OG.

**اعتبار تشغيلي (مؤجّل لـ P4/P6):** صفحات التفاصيل ثابتة (SSG) — بعد نشر رياكشن جديد
من لوحة الإدارة، تظهر على الرئيسية فورًا (جلب حيّ) لكن صفحة تفاصيله ووسوم OG تحتاج
إعادة بناء. سنضيف خطاف "إعادة بناء عند النشر" في P4.

## P4 — لوحة الإدارة الكاملة ✅

**الهدف:** واجهة إدارة SPA منفصلة تتحكم بكل شيء دون لمس الكود.

**ما أُنجز (الخلفية):**
- إعادة هيكلة مسارات الإدارة إلى أربع وحدات: `admin.js` (مصادقة) + `admin-reactions.js`
  (CRUD + رفع + إحصائيات + سجل) + `admin-submissions.js` (مراجعة) + `admin-content.js`
  (تصنيفات/مجموعات/مختار).
- CRUD كامل للرياكشنات: قائمة مرقّمة (بحث + فلترة حالة/تصنيف) + تفاصيل بأي حالة +
  تعديل PATCH (كابشن/موقف/تصنيف/كلمات/مصدر/زاوية/حقوق) + تغيير حالة (نشر/مسودة/أرشفة).
- مراجعة المساهمات: قائمة بحالة + قبول (يعيد معالجة الفيديو عبر خط P2 ويُنشئ رياكشن
  منشورًا بـ `rights_status=original_submission`) + رفض بسبب محفوظ.
- إدارة المحتوى: تعديل التصنيفات (اسم/وصف/ترتيب — **اللون مقفل**) + مجموعات CRUD +
  عضوية (إضافة/إزالة) + مختار الأسبوع (واحد أو أكثر).
- إحصائيات حقيقية مجمّعة من الأحداث: إجماليات + توزيع حالة/تصنيف + الأكثر مشاهدة +
  سلسلة مشاهدات 14 يومًا.
- سجل تدقيق لكل فعل إداري (فاعل + فعل + هدف + ملخص + وقت).
- **خطاف إعادة البناء:** بعد نشر/تعديل/أرشفة/قبول، تُجدول إعادة بناء SSG (debounce 3ث)
  عبر `npm --prefix web run build` — مُختبَر نهايةً إلى نهاية (نشر YR-0013 → وُلّدت
  صفحة `/r/yr-0013` تلقائيًا).

**ما أُنجز (الواجهة — `web/public/admin/`):**
- SPA بنمط Vanilla JS خفيف (لا إطار) تُخدَم على `/admin` (محمية بجلسة HMAC).
- تبويبات: نظرة عامة (رسوم شريطية بسيطة بلا مكتبات) · الرياكشنات (رفع/تعديل/حالات) ·
  المساهمات (قبول/رفض مع معاينة فيديو) · المحتوى (تصنيفات/مجموعات/مختار) · السجل.
- **نظام كابشن "لمّا...":** قوالب جاهزة تملأ حقل الموقف (لمّا صاحبك يقول بكرة، لما حد
  يهرّجك، في القروب لما...).
- **اختصارات لوحة المفاتيح:** A=قبول، R=رفض، ←/→ للتنقل بين المساهمات.
- التوكنز والعلامة مولّدة من `design-tokens.js` (brand.js + tokens.css + حارس drift).

**القرارات المهمة (وانحرافات مبرّرة):**
1. **مختار الأسبوع متعدد** (JSON array بدل قيمة واحدة) — تلبيةً للمتطلب "واحد أو أكثر"،
   مع الحفاظ على توافق الواجهة (البطل يعرض الأول).
2. **قبول المساهمة يعيد معالجة الفيديو عبر خط P2 كاملًا** (ترميز + واترمارك + مصغّرة +
   كشف تكرار) بدل نسخ الملف كما هو — يضمن أن كل منشور من مساهمة يحمل واترمارك العلامة.
3. **خطاف إعادة البناء داخل العملية** (spawn npm build) — يعمل على خادم واحد (تطوير/
   غير Docker)؛ في Docker الإنتاجي لا تتوفر أدوات البناء فيتعطّل بأمان مع تسجيل تحذير
   (الحل الموصى به للإنتاج: البناء في خطوة نشر منفصلة — راجع القرار 4 في P3).
4. **التصنيف: اللون مقفل في الواجهة والخلفية** — حقل اللون لا يُمرَّر ولا يُعدَّل مطلقًا
   (التزامًا بالقاعدة الأولى).

**الاختبارات:** إجمالي 80 اختبارًا يمر (15 جديدة للوحة):
- CRUD: قائمة مرقّمة + بحث/فلترة + تفاصيل + تعديل + تغيير حالة + 400/404.
- مساهمات: قائمة + قبول (رياكشن منشور بواترمارك) + رفض بسبب + 409 للحالة غير الصحيحة.
- محتوى: تعديل تصنيف (اللون ثابت) + مجموعة CRUD + عضوية + مختار متعدد.
- سجل تدقيق + إحصائيات حقيقية.
- **فحص متصفح (Playwright):** دخول + كل التبويبات + بحث + قوالب كابشن → 0 أخطاء console.

**DoD تحقّق:** ✅ المسؤول ينفذ خط الإنتاج كاملًا عبر الواجهة فقط؛ كل فعل مسجّل في سجل
التدقيق؛ خطاف إعادة البناء يعمل نهايةً إلى نهاية.

## P5 — المجتمع والحسابات ✅

**الهدف:** حلقة المساهمة المجتمعية + حسابات بلا كلمة مرور + مزامنة.

**ما أُنجز (الخلفية):**
- **مساهمة عامة** `POST /api/v1/submissions` (multipart): فيديو + موقف + كابشن + تصنيف +
  مصدر + بريد (اختياري) + **إقرار ملكية إلزامي** (يُرفض 400 بدونه). تحقق magic bytes +
  الحجم. حالة Pending دائمًا (لا نشر مباشر).
- **تتبع الزائر:** رقم تتبع `SUB-XXXXXXXX` يُرجع بعد الإرسال + `GET /submissions/:id`
  للاستعلام (بلا فيديو — خصوصية).
- **مساهماتي** `GET /me/submissions`: مساهمات المستخدم بحالاتها + شارة موثوق.
- **ترحيل محفوظات الضيف** `POST /me/saved/migrate`: يدمج قائمة localStorage في الحساب.
- **شارة "مساهِم موثوق":** تُفعَّل عند 3+ مساهمات مقبولة (قابل للضبط عبر
  `TRUSTED_CONTRIBUTOR_THRESHOLD`)؛ تظهر في `/auth/me` و`/me/submissions` وللمسؤول في
  مراجعة المساهمات (`trusted`).
- **إشعارات:** عند قبول/رفض مساهمة يُرسل بريد للمساهم عبر `MailInterface`؛ أُضيف تنفيذ
  **Resend** (HTTP، بلا اعتماديات) بجانب `DevMail` المجاني.

**ما أُنجز (الواجهة):**
- **زر عائم "أرسل رياكشن"** يفتح نافذة من 3 حقول (فيديو + موقف + تصنيف) + كابشن/مصدر/
  بريد اختياري + إقرار ملكية؛ نجاح يعرض رقم التتبع.
- **صفحة `/account`:** دخول OTP بخطوتين (بريد → رمز، الرمز يظهر في وضع التطوير) +
  محفوظات متزامنة + مساهماتي بحالاتها وأسباب الرفض + شارة موثوق + خروج.
- **حفظ متزامن:** زر الحفظ في التفاصيل والبطاقات يزامن مع الخادم عند تسجيل الدخول،
  ويبقى محليًا للضيف؛ ترحيل تلقائي بعد الدخول.
- ربط "حسابي" في الترويسة.

**القرارات المهمة:**
1. **إقرار الملكية حقل منطقي إلزامي في الخادم** (لا ثقة بواجهة فقط) — أي مساهمة بلا
   `ownership=true` تُرفض.
2. **معرّف التتبع أبجدي رقمي بلا التباس** (لا 0/O/1/I) — سهل القراءة اليدوية.
3. **الإشعار عبر البريد يلتقط الفشل بصمت** — لا يكسر دورة القبول لو تعطّل البريد.
4. **حد معدّل المساهمات قابل للضبط** (افتراضي 10/دقيقة) — كان ثابتًا 5 وسقط في الاختبارات.
5. **لا ميزات اجتماعية** (لا متابعة/أصدقاء/تعليقات) — التزامًا بالمبدأ المعماري #1.

**الاختبارات:** إجمالي 92 اختبارًا يمر (12 جديدة):
- دورة مساهمة كاملة: رفض بلا إقرار → إرسال → تتبع → ظهور Pending للمسؤول → قبول
  (رياكشن منشور بحقوق مساهمة أصلية) → رفض بسبب يظهر في التتبع.
- حساب: ترحيل محفوظات الضيف (مع تجاهل المعرّفات المفقودة) + مساهماتي + شارة موثوق بعد 3.
- **فحص متصفح P5:** زر عائم + نافذة مساهمة + صفحة حساب + دورة OTP كاملة → 0 أخطاء console.

**DoD تحقّق:** ✅ غريب يرسل مساهمة → Pending → يقبلها المسؤول → تُنشر → يُشعَر المساهم؛
الحفظ يعمل كضيف ويُرحَّل بعد الدخول.

## P6 — النمو والقانون والإطلاق ✅

**الهدف:** جاهزية الإطلاق العلني 100% (باستثناء البحث الدلالي المؤجل).

**ما أُنجز:**
- **صفحات قانونية:** `/privacy` (جمع البيانات، تجزئة IP، الكوكيز) + `/terms` +
  `/report` (نموذج إبلاغ) — مربوطة في تذييل الموقع.
- **نظام الإبلاغ/Takedown فعّال:** زر "أبلغ" في صفحة التفاصيل → تعليق فوري
  (`status=legal_review` — يختفي من الواجهة) → بلاغ مفتوح للمسؤول → إعادة نشر أو حذف
  نهائي (مع حذف ملفات الوسائط). كل بلاغ يُسجَّل في سجل التدقيق.
- **أمان شامل:**
  - **CSP** على كل استجابات HTML (`default-src 'self'`، `frame-ancestors 'none'`).
  - **CSRF** عبر Origin-check على الطلبات المؤذية (الإدارة/الحساب/المصادقة) + SameSite=Lax.
  - Rate limiting على الإبلاغ/الرفع/تسجيل الدخول/OTP (قابل للضبط).
  - فحص الملفات (magic bytes + حجم + مدة + كشف تكرار) على كل المسارات (إداري + مساهمة).
  - أسرار الإنتاج إجبارية بلا افتراضيات (رفض إقلاع في الإنتاج بقيم ضعيفة).
- **PWA:** `manifest.webmanifest` + service worker (cache-first للأصول، network-first
  للبيانات/الوسائط) + أيقونات مولّدة من القُصاصة (192/512/180) + قابل للتثبيت.
- **نسخ احتياطي ومراقبة:** `scripts/backup.sh` (PG + وسائط + تنظيف 14 نسخة) +
  `scripts/restore.sh` + `/api/v1/health` موسّع (DB + تخزين + ffmpeg + قرص + واترمارك).
- **تعبئة المحتوى:** `scripts/import-content.mjs` يقرأ JSON (metadata + مسارات فيديو)،
  يعالج الفيديوهات عبر خط P2، ويدخلها — مع `DRY_RUN` للمعاينة؛ واجهة تدعم عرض
  "لا يوجد فيديو" بشكل أنيق (metadata فقط).
- **التوثيق:** `docs/DEPLOYMENT.md` (نشر/نسخ/مراقبة) + `docs/LAUNCH.md` (قائمة تدقيق).

**الاختبارات:** إجمالي 110 اختبارات تمر (18 جديدة):
- دورة إبلاغ كاملة (إبلاغ → تعليق → اختفاء من الواجهة → مراجعة → نشر/حذف صلب).
- أمان: CSRF (رفض Origin مختلف/قبول نفسه) + CSP header + رؤوس أمان + health موسّع.
- PWA (manifest + أيقونات + service worker + ربط التخطيط).
- نسخ احتياطي (سكربت ينتج dump صالح) + استيراد (metadata صالح يُدخل، صنف خاطئ يُتخطى).
- **فحص إطلاق نهائي (Playwright):** ديسكتوب + موبايل → واجهة + تفاصيل + قانونية +
  PWA (manifest + SW مسجّل) + لوحة (تبويب بلاغات) → 0 أخطاء console.

**DoD تحقّق:** ✅ Takedown يعمل نهايةً إلى نهاية؛ كل صناديق الأمان ✅؛ PWA قابلة للتثبيت؛
النسخ الاحتياطي والاستعادة يعملان؛ صفحات قانونية جاهزة؛ فحص إطلاق نظيف.

## P6.5 — توحيد نسخة Arena مع نسخة Manus ✅

**الهدف:** اعتماد نسخة Arena أساسًا رسميًا + استرداد المحتوى والميزات المفيدة من
الموقع المنشور (Manus) دون نقل بيانات الاختبار المكررة.

**القرارات (بإجماع المستخدم):**
- نسخة Arena (Astro + Preact + Fastify + PostgreSQL) هي الأساس الرسمي.
- "ضابح" هو اسم فئة anger المعتمد (بدل "غضب") — معرّف الفئة `anger` ثابت.
- لا نقل بيانات الاختبار المكررة (6 رياكشنات "قوية! اختبار مساهمة" متطابقة).
- مستودع GitHub جديد سيُنشأ (المستودع القديم yemreact-platform يبقى مرجعًا لا يُمسّ).

**ما استُرد من Manus (المفيد فقط):**
1. **`searchOptimizer`** — حقل نصي موسّع للبحث باللهجة (هجرة 0006 + بذر + بحث + API +
   رفع/تعديل إداري + استيراد + واجهة الإدارة).
2. **`semanticModel`** — عمود مهيّأ للبحث الدلالي (null حاليًا — مؤجل حتى 300+).
3. **`failed_searches`** — جدول + تسجيل الاستعلامات صفرية النتيجة + مسار إداري
   `/admin/failed-searches` + عرض في لوحة الإدارة (تغذية الفهرس وطابور المحتوى).
4. **المحتوى الحقيقي الوحيد** — رياكشن YR-0020 "مالك دخل" (metadata فقط، الفيديو بقي
   على manus-storage ولم يُنقل) + مجموعة "مصطفى المومري".
5. **`new_count`** — ربط حد "جديد المكتبة" بالإعدادات (كان موجودًا بلا ربط).

**ما أُجّل عمدًا (موثّق للرجوع):**
- نظام video jobs غير المتزامن (المعالجة المتزامنة تعمل وتكفي الآن).
- استيراد دفعة بواجهة (سكربت CLI موجود) + growthFunnel + semanticModel مفعّل.

**الاختبارات:** إجمالي 116 اختبارًا يمر (6 جديدة للتوحيد):
- "ضابح" اسمًا معتمدًا لفئة anger (اللون ثابت).
- YR-0020 موجود بلا فيديو + البحث بـ"مصطفى" يجده عبر searchOptimizer.
- مجموعة "مصطفى المومري" تحتوي YR-0020.
- الاستعلامات الفاشلة تُسجَّل.
- تحديث 4 اختبارات لتعكس الأعداد الجديدة (13 رياكشن / 4 مجموعات).

**تجهيز المستودع:**
- `git init` + commit أولي محلي (141 ملفًا) على فرع `main` — **بلا remote وبلا push**.
- `.gitignore` مكتمل (يستثني node_modules، web/dist، web/.astro، .env، data/، لقطات الشاشة).
- لا تسرب أسرار أو وسائط (مؤكد بالفحص).
